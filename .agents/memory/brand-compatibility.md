---
name: Brand compatibility
description: Rebranding display text without disrupting existing GYM Buddy installs and saved data
---

When changing the GYM Buddy name or visual branding, preserve legacy package, deep-link, pairing, and browser-storage identifiers unless a separate migration is explicitly planned.

**Why:** The app was rebranded from FitPulse while maintaining existing profiles, movement pairing, and mobile installations. These non-visible identifiers remain deliberately stable; renaming them as a text-cleanup step would strand existing data or links.

**How to apply:** Change user-visible copy, icons, metadata, and colors as requested, but treat changes to internal identifiers as a migration requiring compatibility handling.

For name-and-logo requests, keep the existing interface palette and layouts unless the user explicitly asks for a redesign. The user clarified that the broader recoloring and new mobile dark palette were unwanted, so those changes were removed while keeping the new name and logo.

**Why:** A rebrand request is not permission to alter the app's established visual design.

**How to apply:** Scope future brand edits to the requested text, logo assets, and related metadata; ask before changing the broader interface.

The logo should be visibly fitness-related, using imagery such as abs, barbells, weight plates or dumbbells rather than a generic letter mark.

**Why:** The user explicitly said fitness imagery would match what the app is about.

**How to apply:** Use this direction when revising the shared app and website identity, while keeping the name lettering readable at small sizes.
